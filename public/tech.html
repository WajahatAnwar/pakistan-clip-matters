📌 Executive Summary

Clip Matters is an advanced AI-powered video intelligence platform designed to revolutionize how organizations manage, transcribe, search, and analyze video content. The platform automatically processes videos stored in Dropbox, uploads them to YouTube for playback, generates accurate transcriptions with speaker identification, and enables powerful semantic search across all video content.

Business Value

⏱️ Time Savings

Reduce hours of manual video review to seconds with AI-powered search capabilities.

🎤 Speaker Recognition

Automatically identify who said what in multi-speaker videos using voice fingerprinting.

🌍 Multi-Language Support

Supports Urdu, English, and other languages with automatic detection.

✂️ Clip Generation

Create and download specific video segments without external tools.

⭐ Key Features

1. 📤 Video Management

  • Automatic video import from Dropbox
  • Bulk video processing capabilities
  • Progress tracking and status monitoring
  • Automatic YouTube upload (unlisted privacy)

2. 🎤 Transcription & Speaker Identification

  • AssemblyAI for accurate speech-to-text conversion
  • Pyannote AI for speaker diarization and identification
  • Voice sample training for known speakers
  • Multi-language support (Urdu, English, auto-detect)

3. 🔎 Elastic Search

  • Semantic Search: Find content by meaning, not just keywords
  • Fuzzy Matching: Handles typos and spelling variations
  • Speaker Search: Find all segments where a specific person spoke
  • Time-Range Filtering: Search within specific video timestamps
  • Multi-Keyword Search: OR-logic search with multiple terms

4. ✂️ Video Clip Generation

  • Create clips from specific timestamps
  • Download individual segments
  • Timeline-based clip selection
  • Browser-based video trimming (FFmpeg.wasm)

5. 📊 Analytics Dashboard

  • Video processing statistics
  • Search analytics and trends
  • Most searched keywords tracking
  • User activity monitoring

🔄 Complete Workflow

Phase 1: Video Ingestion

┌─────────────────────────────────────────────────────────────────┐ │ VIDEO INGESTION WORKFLOW │ └─────────────────────────────────────────────────────────────────┘ Step 1: Admin selects video from Dropbox │ ▼ Step 2: System creates Video record (status: pending) │ ▼ Step 3: ProcessVideoJob dispatched to queue │ ▼ Step 4: Download video from Dropbox to local storage │ ▼ Step 5: Extract audio from video (FFmpeg) │ ▼ Step 6: Upload video to YouTube (unlisted) │ ▼ Step 7: Send audio to AssemblyAI for transcription │ ▼ Step 8: Send audio to Pyannote for speaker identification │ ▼ Step 9: Merge transcript + speaker data │ ▼ Step 10: Save all data to Video model │ ▼ Step 11: Mark video as completed

Phase 2: Embedding Generation

┌─────────────────────────────────────────────────────────────────┐ │ EMBEDDING GENERATION WORKFLOW │ └─────────────────────────────────────────────────────────────────┘ Step 1: Admin triggers embedding generation │ ▼ Step 2: GenerateVideoEmbedding job dispatched │ ▼ Step 3: Parse identification_data + speakers_data │ ▼ Step 4: Enrich segments with speaker + text │ ▼ Step 5: Send to Railway FastAPI service │ ▼ Step 6: Generate embeddings (sentence-transformers) │ ▼ Step 7: Store vectors in Qdrant collection │ ▼ Step 8: Update VideoEmbedding status: completed

┌─────────────────────────────────────────────────────────────────┐ │ SEARCH WORKFLOW │ └─────────────────────────────────────────────────────────────────┘ Step 1: User enters search query │ ├──────────────────┬───────────────────┐ ▼ ▼ ▼ Semantic Mode Keyword Mode Speaker Mode (query text) (words array) (speaker name) │ │ │ └──────────────────┴───────────────────┘ │ ▼ Step 2: Laravel sends request to Railway API │ ▼ Step 3: Railway performs dual search: ├── Semantic: Vector similarity search └── Keyword: Fuzzy text matching │ ▼ Step 4: Merge and rank results │ ▼ Step 5: Laravel groups results by video │ ▼ Step 6: Apply pagination (10 videos/page) │ ▼ Step 7: Log search to SearchLog │ ▼ Step 8: Return results to frontend

📦 Core Modules

1. ProcessVideoJob

Location: app/Jobs/ProcessVideoJob.php

Purpose: Main processing pipeline for new videos

Key Fields Populated:

  • youtube_video_id, youtube_url
  • transcript_id, speakers_data
  • diarization_data, identification_data
  • language_detected, audio_duration_seconds

2. GenerateVideoEmbedding

Location: app/Jobs/GenerateVideoEmbedding.php

Purpose: Generate searchable embeddings for video transcript

Process:

  1. Parse identification_data (speaker timing)
  2. Parse speakers_data (transcript text)
  3. Enrich segments by matching timestamps
  4. Send to FastAPI embedding service
  5. Store vectors in Qdrant

3. DropboxService

Location: app/Services/DropboxService.php

Capabilities: OAuth authentication, list folders/files, stream large downloads, generate temporary links, handle team/business accounts

4. GoogleApiService

Location: app/Services/GoogleApiService.php

Capabilities: YouTube OAuth authentication, video upload (resumable), token refresh handling, privacy setting management

5. AssemblyAiService

Location: app/Services/AssemblyAiService.php

Capabilities: Audio upload, transcription submission, speaker diarization, polling for completion, Pyannote integration

6. SpeakerTaggingService

Location: app/Services/SpeakerTaggingService.php

Purpose: Map generic speakers (A, B, C) to actual names using timestamp overlap and majority voting

Elastic Features

  • Fuzzy Matching: "Muhamad" matches "Muhammad"
  • Typo Tolerance: "nueral" matches "neural"
  • Partial Matching: "learn" matches "learning"
  • N-gram Similarity: Character-level matching
  • Query Caching: Repeated queries served from cache

Search Request Parameters

interface SearchRequest {
  query?: string;           // Semantic search text
  words?: string[];         // Keyword array
  speaker?: string;         // Speaker filter
  title?: string;           // Video title filter
  language?: string;        // Language filter
  video_id?: number;        // Specific video filter
  min_score?: number;       // Minimum relevance (0-1)
  top_k?: number;           // Max results from service
  page?: number;            // Page number (1-based)
  per_page?: number;        // Results per page (max 50)
  time_range?: {
    start?: number;         // Start time (seconds)
    end?: number;           // End time (seconds)
  };
}

🗄️ Database Schema

Videos Table

CREATE TABLE videos (
    id BIGINT PRIMARY KEY,
    user_id BIGINT REFERENCES users(id),
    dropbox_path VARCHAR(500),
    filename VARCHAR(255),
    extension VARCHAR(10),
    size_mb DECIMAL(10,2),
    title VARCHAR(255),
    description TEXT,
    
    -- Processing Status
    processing_status ENUM('pending','processing','completed','failed'),
    processing_error TEXT,
    processing_started_at TIMESTAMP,
    processing_completed_at TIMESTAMP,
    
    -- YouTube Integration
    youtube_video_id VARCHAR(50),
    youtube_url VARCHAR(255),
    youtube_privacy VARCHAR(20),
    
    -- Transcription
    transcript_id VARCHAR(100),
    transcript_text LONGTEXT,
    language_detected VARCHAR(10),
    audio_duration_seconds INT,
    confidence DECIMAL(5,4),
    
    -- Speaker Data
    speakers_count INT,
    speakers_data JSON,
    diarization_data JSON,
    identification_data JSON,
    speaker_mapping JSON,
    pyannote_job_id VARCHAR(100),
    
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

Video Embeddings Table

CREATE TABLE video_embeddings (
    id BIGINT PRIMARY KEY,
    video_id BIGINT REFERENCES videos(id),
    status ENUM('pending','processing','completed','failed'),
    qdrant_collection VARCHAR(100),
    segments_count INT,
    vector_dimensions INT DEFAULT 384,
    error_message TEXT,
    processing_started_at TIMESTAMP,
    processing_completed_at TIMESTAMP,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

Search Logs Table

CREATE TABLE search_logs (
    id BIGINT PRIMARY KEY,
    user_id BIGINT,
    query VARCHAR(1000),
    word VARCHAR(200),
    speaker VARCHAR(200),
    video_id BIGINT,
    results_count INT,
    videos_count INT,
    min_score DECIMAL(3,2),
    response_time_ms INT,
    ip_address VARCHAR(45),
    user_agent TEXT,
    search_type VARCHAR(50),
    filters JSON,
    created_at TIMESTAMP
);

🔒 Security Features

  • API Key Authentication: All embedding service calls require X-API-Key header
  • Rate Limiting: 100 requests per 60 seconds per IP
  • OAuth 2.0: Secure token-based authentication for Dropbox/YouTube
  • CSRF Protection: All forms protected with CSRF tokens
  • Role-Based Access: Admin and User roles with distinct permissions
  • Input Validation: Pydantic/Laravel validation on all inputs
  • Encrypted Tokens: OAuth tokens stored encrypted in database
